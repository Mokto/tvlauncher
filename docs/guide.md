## Jellyfin

Sign in on the TV, from the **cog** at the top right of Home (press Up from the top row, then OK). Nothing is set up from the Mac.

1. Open **Settings → Profiles → [profile] → Media accounts → Jellyfin account**. The launcher looks for a server with Jellyfin's UDP broadcast (port 7359), trying the address used last time first.
2. If none answers (a server behind a port proxy, as in WSL or Docker, does not get the broadcast), an on-screen keyboard asks for the address. Type a host or IP (`192.168.1.10`; the port is 8096 unless you add `:port`) or a full URL, with the **https://** and **http://** keys to set the scheme. A bare host is tried as `http://host:8096` and then as `https://host`, so `jellyfin.example.com` behind a reverse proxy just works. The remote's number keys and a keyboard's letters work too. **HTTPS goes through the TV's `curl`** (this binary has no TLS), so the server's certificate must be trusted by the TV: a self-signed one is refused.
3. The dialog shows a **Quick Connect** code. On a phone or computer, open a Jellyfin app that is signed in, go to Settings, then Quick Connect, and enter it. Quick Connect must be on in the server (Dashboard, General).
4. The TV then receives its own device login (named `tvlauncher`) and the **Continue watching** row appears. Back closes the dialog at any step.

- The login is saved in `/media/developer/tvlauncher/jellyfin.json` (mode 600: server, user and device token); the last server address is kept in `state.json`. The **Jellyfin account** row offers *Refresh now* and *Sign out*, which revokes the token on the server and deletes the file and the cache. New sign-ins get their own device ID, so signing into a second launcher profile does not replace the first login.
- **Jellyfin external app** under **Media accounts** picks the app that opens an item: it lists the installed apps whose id or name contains "jelly", "moonfin" or "moonfish" (Native Jelly in any build, Moonfin, the official app). The default is `com.sostk.nativejelly.nightly`. The choice is kept in `state.json`.
- **Continue watching** shows resume and next-up items. The focused episode shows its series, season and episode number (for example, *The Bridge · S2 · E1*). On a Manager profile, tap OK to play, or hold OK on the card and choose **Remove from Continue watching** to hide it locally without changing the server. The profile’s `state.json` keeps the last 200 dismissed item keys. The **Continue watching** switch under **Home & tabs** hides the entire row (shown by default); the library tabs and backdrops stay. It is kept in `state.json` (`rowsOff`).
- **Home background:** when the focused card has no picture of its own (an app, an input), the background is a random movie or series backdrop from the signed-in user's library, as on Android TV. The refresh asks Jellyfin for 12 random ones (`SortBy=Random`, only items with a backdrop), saves them as `cache/home-*.img` with the list in `cache/backdrops.json`, and renews the set every 12 hours. The launcher picks one at random each time Home starts or comes to the front, and every 30 seconds while one is showing (`FEATURED_MS`), never the one it just showed; it doesn't change while a menu is open. A YouTube video's picture is only 640 px wide, so as a background it is cut to its middle, averaged down to 32 × 18 pixels and darkened (`blur` in `src/gfx.rs`), which gives a soft glow of its colours instead of a blocky enlargement; the hero title is cut at about 35 characters. LG's own background images for apps are ignored, since they are inconsistent (a dull preview for YouTube, a logo on flat colour for Disney+). The hero area then says what the picture is, as on Android TV: the title of that movie or series, and its year and a short description (about 200 characters), saved with the picture in `backdrops.json`; the focused app's name is the label under its card. A set saved by an earlier version has no text and is fetched again. Cards with their own picture (Continue watching, YouTube) still crossfade to it. The picture shows through the rows at 16 % and through the left gradient at 18 %. Signed out, or with no backdrops, the background is plain dark. Sign-out deletes the pictures. Only the Jellyfin user's own libraries are used, so the backdrops respect the signed-in account’s library access.
- The list (Jellyfin's resume and next-up items) and its pictures are cached in `/media/developer/tvlauncher/cache` and shown at once; a background thread refreshes them on every start, on coming back to the front and on the Home key. The launcher never wakes the tower: when the server is asleep the refresh times out after 6 s and the cached row stays.
- Opening an item starts the chosen app with `{"itemId", "userId", "serverId"}` as launch parameters. Native Jelly's `feat/deep-link-launch` branch (see its `docs/deep-link.md`) turns that into the item's detail page; a build without it, or another app, just opens the app (whether Moonfin reads these parameters is unchecked). The detail page never starts playback itself, and the user must already be signed in inside that app.
- The simulator signs in the same way and writes `fixtures/media/developer/tvlauncher/jellyfin.json`, which is ignored by Git.

### Library tabs

Each film, series or collection library of the signed-in user gets a tab after Home (*Movies*, *Shows*, …); music, books, photo and live TV libraries are left out. A tab shows the focused title's backdrop behind the page, its name, year (a series' years), length, rating, age rating and genres, and the start of its overview, above rows of posters as on Google TV: *Continue watching*, *Recently added*, *Unwatched* (best rated first), a row for each of the eight largest genres, and last *All*, every title in a grid of six to a row (A to Z, or newest first). The rows come from the cached list, so they need no extra requests; a library of fewer than 24 titles is only the grid, and an empty row is left out. Left and Right move along a row (it scrolls, and keeps its place when you come back to it), Up and Down move between rows. A bar on a poster shows how far a film is watched. OK opens the title's page (see [Playing films](#playing-films)), or, with *Play in the launcher* off, the title in the configured external app. Holding OK offers *Sort by name* or *Sort by date added* (for all library tabs, kept in `state.json`) and *Refresh the libraries*. Back goes to the first row, then to Home. The remote's Home key goes back to Home from any tab or page: the app manager ignores it while Home is in front, so the launcher reads the remotes' input devices for it (only reads them; evdev code 773 on the Magic Remote).

- The libraries (`/Users/{id}/Views`) and their titles are cached as `cache/lib-views.json` and `cache/lib-<library>.json` and shown at once; the refresh at start, on coming back to the front, on the Home key and on switching to a library tab asks for new lists when they are more than 5 minutes old, so a title removed on the server is gone the next time you open the tab. The first request has the same 6 s timeout as Continue watching, so a sleeping server is never waited for; a whole library then has 60 s. Posters (300 px wide) are fetched only for the rows on screen and the one below, and the backdrop (1280 px) only for the focused title, as `cache/t-p-<key>.img` and `cache/t-b-<key>.img`. The key is the title's TMDB id (`tmdbm603`, `tmdbtv1668`), which the lists ask both servers for, so a film on Jellyfin and on Plex has one poster and one backdrop on the TV. A title without a TMDB id keeps its own, as `cache/<lib|plib>-p-*.img` and `-b-*.img`. A refresh that brings a new picture tag deletes the cached picture so it is fetched again, and pictures that no library list uses any more are deleted; signing out of one server deletes the pictures only it used.
- Only the posters of the rows on screen are kept as textures, and those of a tab that isn't shown are freed: on the C1, with a library of 400 titles from a fake server, the launcher stayed at about 53 MB after four rounds of scrolling 15 rows down and back, and at about 60 MB with real posters from a 26-film library.

### Search

Press Up from the first row and move Left to the magnifying glass, always the first tab before Home. Press OK to expand the search field. Poster results update with each letter on the on-screen keyboard. Choose **Results**, or move Right from the edge of the keyboard, to browse the posters. OK opens a title; Back returns to the same results, then to the keyboard. Search matches the active profile’s visible cached libraries even offline. Missing posters load in the background if the server is available. Copies with the same TMDB movie or series ID appear once; titles without a shared ID stay separate to avoid merging remakes or unrelated shows. If more than 64 titles match, narrow the search.

## Profiles

Go to **Settings → Profiles** to add a profile. The first profile, **Owner**, is a Manager and keeps the existing setup. Pick a profile from the full-screen **Who’s watching?** page with circular avatars at startup if there’s more than one (or if the only one has a PIN). With more than one profile, the top-left circle shows your picture and expands to show your name when focused. Go Up to the top bar, then Left to the picture and press OK to switch. Press Back in the picker to return to the current profile; Back at startup does not bypass the picker or a PIN. Managers can choose from 38 built-in **Midnight Matinee** pictures when adding a profile, or change the picture in **Settings → Profiles**. Returning from an app or pressing Home keeps the active profile.

- **Manager:** Full access. **Settings → Profiles → [profile]** opens that person’s editor. The avatar and name show who you’re editing; the roster marks who’s watching. **Profile** contains name, picture and PIN. **Media accounts** shows Jellyfin and Plex sign-in status. **Home & tabs** and **Playback** are per profile. **Allowed apps** appears for Kids only. Boot, LG privacy, YouTube, IPTV and receiver setup live under **This TV**; Kids don’t see the shared media sources.
- **Adult:** Full viewing and app access without launcher settings or app management.
- **Kid:** No apps are allowed until a Manager enables them in **Allowed apps**. Kids don’t see TV inputs and use the built-in player for their own Jellyfin or Plex libraries, without falling back to an external app. Sign in with a restricted server account: hidden tabs change navigation, not what the media account can access.

A Manager can optionally set or remove a four-digit PIN on any profile. The keypad submits automatically after the last digit, including for existing longer PINs. Add PINs to unrestricted profiles if you want to prevent children switching to them. PINs protect the launcher’s profile picker only; they don’t restrict webOS, direct remote shortcuts, or what an approved external app can show. Profile names, PINs and allowed apps are kept in the owner-only `profiles.json`; use a PIN you don’t use elsewhere. The existing Plex sign-in flow still applies; the launcher doesn’t switch Plex Home users.

## Tabs

Settings → **Profiles → [profile] → Home & tabs** lets each profile show, hide, rename or move **Home**, Jellyfin and Plex library tabs, and **Live TV** when configured. Press OK on a tab to toggle it, or Right for rename and move options. If Home is hidden, the launcher opens the first visible tab instead. If no tabs are available, Home comes back as a fallback. The tab bar only appears when two or more tabs are visible. Up from the first row reaches it. Left and Right switch tabs (Right past the last one reaches the cog), and Back returns to the start of the tab, then to the profile's landing tab. Clearing a custom name restores the default: library tab names come from Jellyfin or Plex. Tab order, visibility and custom names are kept in the profile's `state.json`.

## Plex

A **Continue watching on Plex** row with what your Plex account is in the middle of, from its own servers.

1. Open **Settings → Profiles → [profile] → Media accounts → Plex account**. The dialog shows a code. On a phone or computer, open **plex.tv/link**, sign in and enter it (this is Plex's own PIN sign-in, the one Plex's TV apps use). Nothing is typed with the remote.
2. The launcher asks plex.tv for the account's servers (its own first, then shared ones, at most three), then asks each for its Continue Watching hub (`/hubs/continueWatching/items`, or `/library/onDeck` on an older server). Movies and episodes are kept, newest first, 15 at most, with a picture and a progress bar. Each server is tried on the home network over plain HTTP first, then over Plex's HTTPS names; relays are never used.
3. With **Play in the launcher** off, OK on a card launches the app chosen under **Plex external app** with Plex's launch link, `{"plex": {"server": "<machineIdentifier>", "ratingKey": "<key>", "action": "open"}}`, which [PlxNative documents](https://github.com/plxnative/plx-native/blob/main/docs/launch-links.md) for launchers like this. It lands on the title's page. The launcher closes the app first and then starts it, because on webOS 6 an app that is already running never reads new launch parameters. The official Plex app has no documented link, so it only starts.

- The token is saved in `/media/developer/tvlauncher/plex.json` (mode 600), with the id this TV gave itself. The list and pictures are cached (`cache/plex.json`, `cache/plex-*.img`), so the row shows at once and also when the server is asleep: like Jellyfin, the launcher never wakes it. **Sign out** deletes the login and the cache here; the token stays valid at Plex until you remove the device under *Authorized devices* in your account settings on plex.tv.
- **Plex external app** under **Media accounts** lists the installed apps whose id or name contains "plex" or "plx". The default is PlxNative (`com.beb.plxnative`) when it is installed, else any Plex app.
- **Continue watching** uses the same season and episode labels and the same local **Remove from Continue watching** action as [Jellyfin](#jellyfin). The profile’s **Home & tabs** settings can hide the row without hiding the library tabs.
- HTTPS goes through the TV's `curl`, like Jellyfin and YouTube. The row is refreshed whenever Home starts or comes to the front.
- **Library tabs:** the film and show libraries of the account's own servers get tabs too, shown exactly like [Jellyfin's](#library-tabs) (shared servers are left out: they would add tabs nobody asked for and fetch whole libraries over the internet). The lists come from `/library/sections` and each section's `/all`, over the address the server answered on, and the pictures from the server's `/photo/:/transcode`. They are cached as `cache/plib-*`; `cache/plib-views.json` also holds the server's address and token for the pictures, so it is mode 600. Tabs keep the library's name; when Jellyfin and Plex both have a *Movies*, rename one under the profile’s **Home & tabs** page. OK opens the title’s detail page by default, or the selected external app with the launch link above if built-in playback is off. When a server doesn't answer, its tabs stay with the cached lists. Sign-out deletes them.

## Playing films

The profile’s **Playback → Play in the launcher** switch (on by default) makes the launcher's own player play Jellyfin and Plex titles instead of opening Native Jelly or PlxNative. OK in Continue watching plays the title at once. OK in a library tab opens the title's page, one page that scrolls down:

- **The top**, over the backdrop: the title's logo (its name when the server has none, or an empty one), *Movie* or *TV Show* with genres and age rating, the resolution and Dolby Vision or HDR, the scores the server has (TMDB on Jellyfin; Rotten Tomatoes, audience, TMDB or IMDb on Plex), the overview, the date, length and sound, director and three actors at the right, and *Play* (or *Resume · 0:42:10*), *From the start* when there is a resume point, and a watched mark (OK marks it watched or not). A series' *Play* is its next episode (the one begun, else the one after the last watched).
- **A series**: its seasons as tabs and their episodes as cards: the still with the length, a mark when watched and a bar for how far, then the episode number, name, overview and air date. OK plays an episode; holding OK offers *From the start* and *Mark as watched*.
- **Cast & Crew**: round photos with the name and the character, then the director and writers (no person page yet).
- **Related**: the titles the server finds similar that a library tab has. OK opens that title's page; Back returns to the page before. Up from the buttons at the top reaches the tabs and the cog; Down returns to the page, another tab closes it.
- **About**: the overview in full (OK on the card shows all of a long one), then *Information* (release date, run time or seasons and episodes, age rating, studio), *Languages* (original language on Jellyfin, every audio track, the subtitle languages) and *Accessibility* (SDH, closed captions, audio description, when a track says so). A series takes its languages from its next episode.

Plex detail pages are cached separately for each server. After upgrading, open a title or refresh its library while its server is online to populate the new cache.

The page comes from the server (`detail.rs`): the title, its similar titles, a series' episodes and its next episode, each in its own request. Only the fields the page reads are saved, as `cache/lib-d-<id>-page` or `cache/plib-d-<server>_<id>-page` (about 15 KB a page; Friends on Plex is the largest at 155 KB), so a page shows at once from the saved copy while the server is asked again, and is drawn again only if the answer differs (with the server asleep the saved copy stays). Right after a library's list comes from its server, a background thread saves every title's page (again when more than a day old) and the pictures a page shows first: the logo, the first 8 cast photos (176 px, the size drawn), the related posters and the stills of the season it opens on. Other seasons and the rest of the cast load when you reach them, and stay cached. The first request that fails stops it. The TV's apps install and update on the partition the cache is on, so the fill watches its free space: under 300 MB it saves artwork only (no cast photos), and under 200 MB it deletes cast photos, then episode stills, oldest first, until 220 MB is free, and stops if that isn't enough. Posters, backdrops and logos are never deleted for room, and pages still load what they show when opened. A title's page pictures are kept once for both servers, under its TMDB id (`cache/t-e-tmdb<m|tv><id>-*.img`; a title without one keeps its own, `cache/<lib|plib>-e-*`), and are deleted once no saved page uses them. The shared names leave out the servers' picture tags (they differ), so when a server's answer brings a new tag for a picture, the cached one is deleted and fetched again. For 26 films and 4 series, each on both Jellyfin and Plex, the page pictures took 5.7 MB with 240 px cast photos. Plex fetches cast photos from plex.tv and scales them. Marking a title watched deletes its saved page, so the next visit waits for the server. A collection, and anything the player cannot start, still opens in the app.

- **A process of its own.** The launcher starts itself as `tvlauncher --film <item>` and waits. That process opens its own window and LG's player, so a crash during a film takes down only the player: Home keeps running, and the player's memory is freed when the film ends. Back ends the film and brings Home back; the Home key does too (the launcher registers with the app manager while a film plays, so the key arrives as a message, and it stops the player first so the server hears where you stopped; it ends the registration afterwards, because a registered Home in front does not hear the key at all). The player's window has an app id of its own (`tvlauncher.player`): with Home's id the app manager thinks Home is already in front and ignores the key.
- **The file is played as it is.** The player reads the Matroska or MP4 file of the title over HTTP with the TV's `curl` (byte ranges: it needs a server that does ranges, as Jellyfin and Plex do), cuts it into H.264, H.265, AV1 or VP9 pictures and audio frames with FFmpeg, and feeds LG's decoder the same way it does for a channel. AV1 (Main profile, 8 and 10 bit) and VP9 (profile 0, 8 bit) play only on a TV whose own decoder table (`/etc/umediaserver/device_codec_capability_config.json`) lists them, as the C1's does; AV1 is sent as Section 5 temporal units with its sequence header in front of each keyframe, the framing Native Jelly found the decoder needs, and an AV1 Dolby Vision profile 10 stream is declared as Dolby Vision. Nothing is transcoded: the server only sends the file. FFmpeg is three libraries in `lib/` (about 1.5 MB, LGPL, see [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)), loaded at run time; without them every film is converted by the server, as below.
- **Audio:** AAC, AC-3 and E-AC-3 (Atmos included) go to the TV as they are. TrueHD, FLAC, ALAC, Vorbis and PCM are decoded and sent as AC-3 (5.1 at most; 7.1 is folded into 5.1), which costs the TV about 14 % of one core for TrueHD 7.1 in Native Jelly's measurement. The *Audio* button lists every track.
- **Subtitles:** text tracks (SRT, MOV text, WebVTT) are shown as plain lines (a line placed at the top stays at the top), and picture tracks (PGS from Blu-rays, DVD VobSub, DVB) are drawn as the bitmaps they are. An ASS or SSA track inside the file is drawn with its styling by libass (fonts, colours, outlines, positions, signs, karaoke, with the fonts attached to the file and the TV's UI font for the rest): it is a fifth library in `lib/` (about 2.6 MB, with FreeType, HarfBuzz and FriBidi inside), and without it the lines are plain text. Two limits: a line that began before the place the film starts or seeks to is not shown until its next appearance, and a script that names a font that is neither attached nor the TV's falls back to the UI font, which lacks CJK. Subtitle files beside the video (which only the server has) are fetched and shown as plain lines. When the playback controls appear, subtitles that would overlap the bar move up, then return to their usual position when the bar closes.
- **Dolby Vision and HDR10:** a Dolby Vision profile 5 or 8 stream is declared to LG's player as Dolby Vision on a TV that reports support; HDR10 needs nothing. A profile 7 disc (a UHD Blu-ray remux) has two layers and LG's decoder takes one: on a Dolby Vision TV the enhancement layer is dropped and the metadata rewritten to profile 8.1 (what `dovi_tool -m 2` does) and declared as profile 8, so it plays in Dolby Vision. A *minimal* enhancement layer, which is only metadata, loses nothing; a *full* one also carries residual detail, which is lost, as on every single-layer player (the base picture and its dynamic metadata stay). On a TV without Dolby Vision, or for a file whose layers do not fit this (profile 7 needs a cross-compatible base), the HDR10 picture plays. **HDR10+:** LG TVs do not support it and the decoder can stall on its per-frame messages, so they are cut out of every H.265 picture and an HDR10+ film plays as plain HDR10 (the static HDR10 values stay).
- **Lossless audio to a receiver** (the profile’s **Playback → Lossless audio to a receiver**, off by default; adapted from [the author's Native Jelly implementation](https://github.com/sostk/native-jelly/pull/46)): DTS and DTS-HD MA, which the TV cannot decode, are sent unconverted to an AV receiver; Dolby TrueHD (Atmos), DTS:X and high-bitrate DTS-HD MA also need the root module below (without it TrueHD is converted to AC-3 and DTS:X plays as DTS-HD MA or its core). Set the TV's Digital Sound Output to Pass Through. It only applies while the TV's sound output (`getSoundOutput`) is HDMI ARC / eARC or optical; on TV speakers, headphones or Bluetooth the bursts would be noise, so those play as without the switch. LG's player is told the film has Dolby Digital Plus audio and is fed silent E-AC-3 frames; LG's audio libraries, which run in the player's process, pack each frame into an IEC 61937 burst and write it with `ioctl`, which the executable exports (`src/ff/lossless.rs`), so the player swaps the burst for the real DTS-HD or TrueHD data of the same 32 ms. LG keeps the timing, the sync, pause and seeking. There are three routes, chosen per title: DTS-HD MA and DTS:X at full rate and TrueHD / Atmos on an 8-channel 192 kHz link (the *HBR* kernel module below); DTS-HD MA on a 192 kHz stereo link without it (a frame too big for the burst sends its core); and, if LG makes no write within the first three seconds (a receiver that takes no Dolby Digital Plus), the DTS core as IEC 61937 declared as PCM, which any receiver on ARC or optical takes. TrueHD without the module is converted to AC-3 as before. **Settings → This TV → Receiver setup → Atmos, TrueHD and DTS:X (root)** installs the module ([Mokto/earc_route](https://github.com/Mokto/earc_route), GPL-2.0-only, a separate program that is never linked, with its source in the package): it is built for webOS 6 (kernel 4.4.84) and was tested only on an LG C1, firmware 03.53.45; other TVs refuse it and keep the stereo link. It loads again at every start (a hook in webosbrew's `init.d`) and *Remove* undoes it. The author has verified tvlauncher’s passthrough on a real receiver. The linked Native Jelly PR records the original format-by-format results on an LG C1 and Sony STR-DN1080. For simulator checks, `sh tools/film-sim.sh` with `FILM_RECEIVER=1` exercises the carrier and fallback to the PCM core against a fake player library.
- **What the server converts:** a file the TV cannot decode as it is (10-bit H.264, 10-bit VP9, AV1 or VP9 on a TV without those decoders, DTS or Opus audio, a server without byte ranges, FFmpeg missing) is played through the server's HLS transcode, the way Live TV reads a channel. The server copies H.264 and H.265 and converts the audio to AC-3, so the cost on the server is usually small, but an AV1 or VP9 picture is a real transcode. Opus stays with the server: Native Jelly's own tests stalled on 5.1 Opus, and it has not turned Opus on either. Picking a DTS track in the audio menu moves the film to the server from there; picture subtitles are not available in that mode. The same happens if the TV's player refuses or fails on the file's stream.
- **Languages:** The profile’s **Playback** page has an *Audio language*, a *Subtitles* mode (the server's choice, off, always on, forced only, or foreign audio only) and a *Subtitle language* (the audio language when blank). They are kept on the TV and apply to Jellyfin and Plex titles, unlike Native Jelly's, which edit the Jellyfin user on the server. A film starts with the first track in that language (any spelling of its code: `fre`, `fra`, `fr`), else with the track the server would start with; a track in the file counts as forced when its forced flag is set, and Jellyfin and Plex say it for their own. You can always pick another track in the player.
- **Chapters, skipping and thumbnails:** a title's chapters show as ticks on the bar with the current one's name, are listed under the bar's *Chapters* button, and Page Down and Up on a keyboard jump to the next or previous chapter (the Magic Remote's channel keys do not reach apps). Jellyfin's media segments (10.10 and later; the Intro Skipper plugin writes them too) and Plex's intro and credits markers put a *Skip intro*, *Skip recap* or *Skip credits* button on screen while they run: OK skips (the Play and Pause keys still pause), and skipping credits to the end of an episode goes to the next one. While you seek, a thumbnail of the place you are heading to shows above the bar: Jellyfin's trickplay sheets, or Plex's BIF index, fetched in the background. A server without them shows nothing.
- **Direct Play and quality:** The profile’s **Playback → Direct Play** is *Automatic* (the file as it is, the server only for what the TV cannot play), *Off* (the server always converts) or *Forced* (never falls back: it says why a file will not play, which is what to use to find out what the TV refuses). *Streaming quality* caps what the server may send when it converts (Maximum, or 40 down to 2 Mbps).
- **Controls:** OK pauses and resumes when no other action is focused. The dedicated Play/Pause key also works with a button or panel focused. Up shows the seek bar over a dark fade, with a playhead and the time the title ends at. Back cancels a pending seek, closes an open panel, or hides the controls before leaving the player. Hiding the controls doesn’t resume a paused film. A tap of Left or Right skips by the *Skip by* step (10 seconds unless changed; the rewind and fast-forward buttons skip 30), and quick taps in the same direction build up to 2×, 4× and then 8× that step from the third tap onward. Reversing direction starts at the normal step. Holding Left or Right still scrubs continuously (20, 60, 180 then 480 seconds of film per second). The chevrons beside the time offset show direction and speed, with the destination time and chapter above the bar, plus a thumbnail when available. The player goes there 0.6 s after the key is let go, or at once with OK (also while holding); Back while seeking stays where you were. A seek starts the player again at the new place, on the keyframe at or before it, so it takes about a second and can land a few seconds early.
- **Buttons:** Down moves from the seek bar to the buttons below it; Up returns to the seek bar. The buttons are *Subtitles*, *Audio* and *Chapters* (each only when there is something to choose), *Options* and *Info*, each with its icon. Left and Right move between them, OK opens one as a panel at the right, Back or Left closes it; a tick marks the current choice. *Subtitles* lists the tracks under their languages, the one you read first (the *Subtitle language* setting, else the audio's), and in each the full track, SDH, forced and commentary, with the format (SRT, ASS, PGS...) at the right. Tracks with the same label and format in a language are numbered separately. *Options* has the subtitle size (Small, Normal, Large, Huge; picture subtitles grow too), their position (Low, Higher, Highest), their colour (white, or grey at 85 % down to 40 %, softer on an HDR picture; it dims picture and ASS subtitles too), their background (a box, or an outline), their timing (0.1 s steps, for this film only) and the skip step (5 to 60 s); all but the timing are kept in `state.json`. *Info* has *Play from the beginning* and *Go to series* (or the film's page: the player closes and Home opens the page, when a library tab has the title), then says how the title comes (the file as it is, or converted by the server), the picture (codec, size, Dolby Vision or HDR as the TV reports it), the audio track and how it reaches the speakers (as it is, converted to Dolby Digital on the TV, or unconverted to the receiver), the subtitles and how many seconds the TV has buffered.
- **Two subtitle languages:** Select a text track in *Subtitles* first, then open *Second subtitles* and choose another track. The first stays at the bottom and the second appears at the top. Choose *Off* in the second menu to keep only the first. This works with embedded and server-served plain text tracks such as SRT, without requiring video transcoding. Bitmap and styled ASS tracks remain single-track. Both tracks share the subtitle timing adjustment; the second selection lasts for the current title.
- **Loading:** the first start shows the title and a moving loading indicator over blurred cached artwork, or a dark background if no artwork is cached. Artwork fades in when ready without holding up playback. After eight seconds, the label shows what the player is waiting for. The overlay fades out as playback starts. A seek or a track change shows only the spinner over the bar. A paused film shows a pause sign in the middle.
- **Resume and progress:** a film resumes from its saved place (between 30 seconds in and 95 %). The server is told when it starts, every 10 seconds, on pause and when it stops (Jellyfin's session reports; Plex's timeline, with a watched mark at the end), so it shows in Continue watching.
- **Next episode:** the profile’s **Playback → Next episode**. *Countdown* (the default) asks the server for the next episode a minute before the credits and shows an *Up next* card when they begin (the credits the server marked, else 20 seconds before the end): it starts in ten seconds, which fill the *Play now* button; OK on *Play now* starts it at once, *Watch credits* or Back keeps watching, and a seek back before the credits brings the card again. *After credits* shows the card only when the episode ends, for five seconds. *Off* stops at the end. The next episode is the one after this one in the series (Jellyfin's episode list from this one, Plex's `allLeaves`).
- **Not there:** a full Dolby Vision enhancement layer's detail, HDR10+ (the TV has none), 3D, and a quality ladder for the server's HLS (it is one stream, capped by *Streaming quality*).
- **Checked without a TV:** `cargo test --release` covers the NAL and ADTS framing, the audio mix, the subtitle parsers, the queue, the title parsing for both servers and the stream addresses. `tvlauncher --direct <url> [seconds [audio [subtitle]]]` reads a file the way the player does and counts what comes out, which is how Matroska and MP4 files with H.264, H.265, AC-3, E-AC-3, AAC, FLAC and TrueHD audio and SRT and ASS subtitles were tried against a local server. `--film-shot out.bmp [seek|seek-no-thumb|buttons|options|subs|info|next|load|bitmap|bitmap-hidden] [backdrop]` draws the controls in that state over a stand-in picture or the supplied 16:9 image, and `sh tools/film-sim.sh "3:enter,5:enter,7:right,16:esc,17:esc"` runs the whole player on a desktop against a fake Jellyfin and a fake player library, with those keys pressed at those seconds (pause, resume, seek, track menu, subtitles, reports). What only the TV can show, and has not been checked: that LG’s decoder accepts these streams, seeking, Dolby Vision, and picture subtitles. On the TV, writing `film:<item>` (a Jellyfin id, or `plex:<server>:<rating key>`) to `/tmp/tvlauncher-spawn` starts a film from SSH, and `/tmp/tvlauncher-player.log` is the player's log.

When a film is being converted by the server, **Info → Why** shows whether Direct Play was turned off or why the player switched to server conversion. It shows a short explanation, not the raw device or network error.

## Hiding and moving apps

**Hold OK** on an app for about 0.7 s, as on LG's own Home (`H` in the simulator; a white bar fills along the card while you hold). A tap still launches it, on release. The menu has *Move*, *Pin to Home* or *Unpin*, and *Hide from Home*:

- **Move**: Left and Right move the card, OK drops it, Back puts it back.
- **Hide from Home**: the app leaves the row. A **Hidden apps (n)** card at the end of the row shows the hidden ones again, dimmed; holding OK on one gives **Show on Home**.

The menu also offers **Uninstall** for apps the TV marks removable, with a confirmation step. The Homebrew Channel and CleanYourTV are excluded.

The choices are kept in the profile’s `state.json`. Apps that are not in the saved order follow in the TV's own order, so a new app lands at the end. Back is `wcode` 482 (seen on this TV). The yellow button (488) still opens the same menu, without any hint on screen. Keys held down repeat for navigation, but OK acts once; the hold is measured from the first press, and the launch waits for OK's release event, which arrives on this TV.

## YouTube recommendations

A **Recommended on YouTube** row with the home feed of YouTube's own TV app, for the account you sign in with. **Unofficial**, the way [SmartTube](https://github.com/yuliskov/SmartTube) does it (its `MediaServiceCore` is the reference): Google has no official recommendations API.

1. **Settings → This TV → Shared media → YouTube account**. The launcher reads the OAuth client of YouTube's TV app from `youtube.com/tv`, asks for a device code and shows it with the page to enter it on (`google.com/device`). Enter it on a phone, with the account you want (a spare one is fine).
2. It then asks `youtubei/v1/browse` (`browseId: default`) as the `TVHTML5` client with that account's token, keeps the video tiles, and downloads their thumbnails. The list and pictures are cached in `cache/youtube.json` and `cache/yt-*.img`, so the row shows at once.
3. OK on a card opens the TV's YouTube app (`youtube.leanback.v4`) with `{"contentTarget": "v=<id>", "contentId": "v=<id>"}` (the first is what webosbrew's youtube-webos reads, the second what Home Assistant sends). Nothing is played by the launcher and no stream is fetched.

- HTTPS goes through the TV's **`curl`**, with the config on stdin so tokens never appear in the process list. If `curl` is missing or cannot verify YouTube's certificate, the row stays empty and `/tmp/tvlauncher.log` says `youtube: curl: ...`.
- The feed is asked for at most every 30 minutes, whenever Home starts or comes to the front; **Refresh now** in Settings forces it. The tokens are in `/media/developer/tvlauncher/youtube.json` (mode 600). **Sign out** revokes the refresh token at Google and deletes the file, the list and the pictures.
- The token is YouTube's TV app's own, with the power of that app on the account (not read-only). You can also revoke it at `myaccount.google.com/security`, under connections to third-party apps ("YouTube on TV").
- It can break whenever YouTube changes the client version, the sign-in or the shape of the answer. The client version is read from `youtube.com/tv` on each refresh. If the answer holds no videos, the log says `youtube: no videos in the answer (logged_in ..., error ..., keys ...)`; `logged_in "0"` means YouTube did not accept the token. This is against YouTube's terms in the way SmartTube is; the launcher only reads the feed, a few times a day.
- Tests that need no account: `cargo test --release` parses a real browse answer (`tests/tv-browse-sample.json`, tiles from YouTube's logged-out music page, with a made-up resume bar and a Short), finds the OAuth client in a script, and quotes curl's config.

## Blocking LG's ads and telemetry

Four switches under **Settings → This TV → Ads and privacy**, **off by default**: *Block ads*, *Block viewing tracking*, *Stop telemetry logs* and *Stop suggestions*. They are [`debloat.sh`](../debloat.sh), ported from CleanYourTV's `debloat-stop.sh` and `debloat-undo.sh` (MIT, credited in the script), with its fixes for HBO Max and Disney+ kept.

| Switch | What it stops |
| --- | --- |
| Block ads | `adoverlay-service`, and `eic.ads.lgtvcommon.com`, `nl.ad.lgsmartad.com`, `nl.info.lgsmartad.com` (plus the TV's own country, for example `dk.ad.lgsmartad.com`) in `/etc/hosts`, marked `# tvlauncher-debloat`. `admanager` is left running: HBO Max and Disney+ wait for it at start. |
| Block viewing tracking | `acr2`, which recognises what is on screen and reports it (LivePlus). |
| Stop telemetry logs | the services `remotelogger` and `service-logger`. |
| Stop suggestions | `contentminer`, `nudge` and `sportsalarm`. |

- A program that luna starts on demand is kept from starting by a do-nothing stub bind-mounted over it; the real file is not changed. Where `/etc/hosts` is on the read-only partition, a copy is mounted over it. Everything is RAM-only, so a reboot undoes it, and nothing is uninstalled.
- It applies only while this launcher is Home: `takeover.sh on` applies the chosen switches, `takeover.sh off` (also the crash watcher) undoes them before LG's Home returns, because LG's Home needs those services. A switch takes effect at once. The chosen groups are the `debloat` list in `state.json`.
- It does not block firmware updates or claim to remove all tracking.
- `sh debloat.sh off` by hand puts everything back, and so does a reboot. `sh tools/debloat-test.sh` runs the script against fake files and commands and checks the stubs, the hosts lines, idempotence and the undo.

## Live TV

Settings → **This TV → Shared media → Channels** takes your own M3U playlist address, or an Xtream Codes login (server, user name, password), typed on the on-screen keyboard. The login is kept in `iptv.json` (mode 600) and only there; no playlist, channel or logo comes with the launcher. Once it is set, a **Live TV** tab appears at the top (see [Tabs](#tabs)).

- **The Live TV tab** is a programme guide: the channels down the left (Favourites first, marked with a yellow dot, then the playlist's order, with their number and logo) and two hours of programmes across, with a line at the current time. Above the grid, the focused programme: title, times, channel, category, episode title and the start of its description. Left and Right move through a channel's programmes (the grid scrolls through the day), Up and Down change channel near the same time, and Back returns to now before it returns to Home. OK on a programme that is on plays the channel; OK on a later one opens its details (the whole description, OK to watch the channel, Back to close). Holding OK offers *Programme details* and *Add to Favourites* or *Remove from Favourites* (kept in `state.json`). Channels the guide does not know show *No programme information* and still play.
- **Watching:** full screen, with a banner of the channel and its programmes for a few seconds. Up and Down change channel through the whole list, OK shows the banner again, Back returns to the guide. A channel that does not play says why on the banner.
- **The guide:** an XMLTV file, from Settings → **This TV → Shared media → Guide**, else the playlist's `url-tvg`/`x-tvg-url`, else the Xtream server's `xmltv.php`. It is read as it downloads (a `.gz` one through the TV's `gzip`), and only the next 24 hours of the playlist's channels are kept (at most 48 programmes each, descriptions cut at 600 characters), so a guide of a hundred megabytes never sits in memory. Channels are matched on `tvg-id` (or Xtream's `epg_channel_id`) without a feed suffix, so iptv-org's `TF1.fr@SD` finds `TF1.fr` in a guide such as xmltvfr.fr's.
- **Caching:** the channel list (`cache/iptv-channels.json`, fetched again after 12 hours or with *Refresh now*), the guide (`cache/iptv-guide.json`, after 2 hours) and the logos of the channels on screen (`cache/iptv-logo-*`) are kept, so the tab shows at once. *Remove* deletes `iptv.json` and that cache.

**The player** ([src/player.rs](../src/player.rs)) is built in, not handed to another app. The TV's `curl` reads the stream, [src/ts.rs](../src/ts.rs) cuts the MPEG-TS into pictures and audio frames, and they are fed to LG's StarfishMediaAPIs (`libplayerAPIs`) in buffer mode, as Native Jelly's player does. The picture is in an SDL exported window under the launcher's transparent one (webOS 5 and later). What it took on the C1:

- LG's library registers bus names that Home's role does not allow, and calls `exit()` when refused. `takeover.sh on` bind-mounts a copy of Home's role (`/usr/share/ls2/roles/{pub,prv}/com.webos.app.home.json`) that adds them (the names in Native Jelly's role) and runs `ls-control scan-services`; `off` unmounts it. RAM-only like the other mounts.
- The media resource manager never gives a decoder to a pipeline whose `appId` is `com.webos.app.home` (`601 Resource Allocation Error` after 20 s), so the pipeline carries `tvlauncher`. The video output then shows it only once `luna://com.webos.media/notifyAppLifeStatus` says that app is in the foreground.
- Each channel gets a new player object and exported window, and the old object is destroyed after its `UNLOADCOMPLETED`: the video output never shows a second pipeline of the same object.
- Play is called once 0.7 s is buffered, and the feed stays at most 1.6 s ahead of the clock; fed greedily, the pipeline stops pulling and never starts.

**What plays:** MPEG-TS over HTTP or HTTPS (an Xtream `.ts` address, most `/live/` playlist entries), and live HLS (`.m3u8`) whose segments are MPEG-TS, with H.264 or H.265 video and AAC, AC-3 or E-AC-3 audio. For HLS ([src/hls.rs](../src/hls.rs)) the player takes the variant with the most bandwidth, starts three segments before the live edge and reads each new segment into the same demuxer. Streams and playlists are fetched with a browser's User-Agent (some channels refuse others), and relative addresses are resolved against the address after redirects. **Not yet:** encrypted HLS (Pluto TV's AES-128 segments, which also bring audio in a playlist of its own), HLS with MP4 segments or separate audio, switching variants on a slow network, and MPEG-1 Layer II audio, which many broadcast channels use (such a channel plays without sound, or not at all). Films and series in an Xtream playlist are left out.

**Memory:** about 40 MB on Home with a playlist of 21 channels; once a channel has played, LG's player libraries stay loaded, about 83 MB, and about 95 MB while a channel plays, steady over 30 channel changes.

**Testing:** `LAUNCHER_ROOT=/tmp target/release/tvlauncher --play <url>` reads ten seconds of a stream on a desktop and prints the codecs and what the TV would be fed. On the TV, a channel number or a stream address in `/tmp/tvlauncher-play` makes the next start of the launcher play it, and `luna://com.webos.service.networkinput/sendSpecialKey '{"key":"UP"}'` presses a remote key (also `DOWN`, `LEFT`, `RIGHT`, `ENTER`, `BACK`). `luna://com.webos.service.capture/executeOneShot` captures the screen with the video.

## Why it runs as LG's Home

A sideloaded native app runs jailed as `prisoner`. The jail has no `/usr/palm/applications`, and luna refuses `listApps` there (`Denied method call "listApps"`). So `takeover.sh on` bind-mounts the binary over `/usr/bin/com.webos.app.home`, and the app manager starts it as Home, as root, outside the jail. The mount is RAM-only: a reboot brings back what was Home before (CleanYourTV's stand-in on this TV).

## Build, try and undo

Needs rustup with a nightly toolchain that has `rust-src`, the webOS NDK at `~/webos-ndk` (Native Jelly's `make setup-env`) and, for the simulator, Homebrew `sdl2` (or `sdl2-compat`), `sdl2_image` and `sdl2_ttf`.

```sh
make arm                   # target/arm-unknown-linux-gnueabi/release/tvlauncher
make sim                   # desktop window against fixtures/ (arrows, Enter, Esc quits)
make shot KEYS=RRD         # build/shot.png after those presses, no window interaction
make deploy on             # copy to /media/developer/tvlauncher and make it Home
make deploy off on         # after a rebuild: the mount pins the old file
make off                   # back to the previous Home and restart CleanYourTV's watchdog
```

`make sim` pulls `fixtures/` from the TV the first time (`tools/pull-fixtures.sh`): launch points, inputs, their images and the LG fonts. It is gitignored because the artwork belongs to the app vendors.

If CleanYourTV is installed, the launcher won't offer to uninstall it from the menu: that only removes its apps, not its boot scripts. Remove it with its own `sh /media/developer/cleanyourtv/uninstall.sh` over SSH (it removes everything and reboots the TV; with *Start as Home* on, the launcher is Home again after the reboot, which was checked on the C1). Nothing here needs CleanYourTV.

`on` stops CleanYourTV's watchdog until `off` or the next reboot, because the watchdog puts its own Home back when its stand-in is not running. The launcher logs to `/tmp/tvlauncher.log` on the TV.

**Start at boot** is an option, off until chosen: Settings → This TV → Startup → **Start as Home**, or `make boot` / `make unboot` from the Mac (both run `takeover.sh boot on|off`). It links `boot.sh` into webosbrew's `/var/lib/webosbrew/init.d` as `20-tvlauncher-home` (so the TV needs the Homebrew Channel's startup). If CleanYourTV is installed, it also creates CleanYourTV's own `DISABLE` file (the switch in its manager that selects LG's Home; its service and manager app keep running, so nothing of it is removed), and removes that file again only if the option set it (marker `made-cytv-disable`). `boot.sh` waits (up to one minute) until the app manager answers and foreground queries work, then runs `BOOT=1 takeover.sh on`, which doesn't open Home if the TV started on an input or an app. On cold boot the launcher paints cached rows first and loads apps and inputs from the bus on a thread. It doesn't block the other boot hooks. If the launcher binary is missing, nothing happens and the TV has LG's Home (CleanYourTV stays off through `DISABLE`). To skip one boot, `touch /media/developer/tvlauncher/NOBOOT` over SSH; to go back, switch the option off (CleanYourTV's Home returns if it was in use). Verified on the C1: a full reboot started the launcher as Home. **Early start.** The webosbrew hooks run only 35 s or more into a boot, and LG's Home is on screen from about 18 s, so `boot.sh` alone shows LG's Home for a while after every power-on (on this TV a power-off sometimes reboots it into a snapshot, and with Quick Start+ off every power-on is a cold boot; a power-off that only suspends keeps the launcher running and needs none of this). Turning *Start as Home* on therefore also installs a second, earlier path, the approach [Luma](https://github.com/ecklf/lg-luma) found: a dynamic LS2 service `com.webos.service.tvlauncherearly` (four small files in `/var/luna-service2`, which `ls-hubd` reads at core-boot-done, about 13 s) whose program is `/var/lib/tvlauncher/early.sh`, and a key-filter script `/var/lib/tvlauncher/home-filter.js` that LG's compositor loads at boot (added to configd's `com.webos.surfacemanager.keyFilters`; it only pings the service, with try/catch around everything, and keys pass through unchanged). The ping runs `takeover.sh early` as root: the bind mount, the role, the crash watcher, then LG's Home is stopped and, if the TV did not start on an input or an app, Home is launched. On the C1 it ran at 21 to 26 s of uptime. `boot.sh` still runs later and, finding the launcher already Home, only applies the debloat switches (and launches Home if nothing did). Switching the option off removes the service files, the script and the filter entry (`sh tools/early-test.sh` checks the add and remove against a fake configd). If the early path fails for any reason the old path still makes the launcher Home. A launch the app manager makes in the background (`reason: preload`) opens no window, so the launcher does not cover the input the TV started on; a real launch ends that process and starts a new one. The crash watcher still applies: three crashes in a minute put LG's Home back until the next reboot, and the next boot tries again.

### Fallback

`on` also starts a small watcher (`takeover.sh watch`, pid in `/tmp/tvlauncher-watch.pid`). The launcher appends a line to `/tmp/tvlauncher-crashes` when it fails to start or dies on a signal (SEGV, ABRT from a panic, and so on). Three of them within a minute run `takeover.sh off`, which puts LG's Home and CleanYourTV's watchdog back, and the watcher writes why to `/tmp/tvlauncher-watch.log`. Not covered: a launcher that hangs without crashing; `make off` or a reboot fixes that.

### Registering with the app manager (opt-in)

Without it the app manager restarts the launcher on every Home key. With a file `/media/developer/tvlauncher/register` present, the launcher registers as Home through `luna-send -i -a com.webos.app.home .../registerApp`, as CleanYourTV's stand-in does: the Home key then arrives as a `relaunch` event (the launcher raises its window, reloads and focuses the first card), `close` ends it, and when the app manager goes away the launcher exits so the next Home starts a fresh one (the app manager restarts at standby). It is off by default because nobody has seen the window come to the front on a relaunch on this TV. If the Home key shows nothing, remove the file and run `make deploy off on`.

### The ARM build

- It is built with `-Zbuild-std`, `target-cpu=cortex-a9` and NEON off ([.cargo/config.toml](../.cargo/config.toml)), as Native Jelly does. The precompiled std for `arm-unknown-linux-gnueabi` emits the ARMv6 CP15 barrier (`mcr p15`), which is undefined on the C1's Cortex-A53 and raises SIGILL. `objdump -d` of the result must show no `p15`. Do not set `RUSTFLAGS`: it replaces the flags in the config file.
- The NDK links against glibc 2.12, which has no `getauxval` (std calls it when it starts a thread), so [src/compat.rs](../src/compat.rs) supplies one. [tools/arm-gcc](../tools/arm-gcc) is the linker: the NDK gcc has no default sysroot.
- The binary is about 2.1 MB (the C version was 50 KB, with std statically linked).

## Release builds

`make release` builds the package. Releases are automated. Every push to `main` runs the checks and builds the package ([build.yml](../.github/workflows/build.yml)). [release-please](https://github.com/googleapis/release-please) reads the commit messages ([Conventional Commits](https://www.conventionalcommits.org): `feat:`, `fix:`, ...) and keeps a release pull request open that bumps the version in `Cargo.toml` and writes `CHANGELOG.md`. Merging that pull request creates the tag and the GitHub release (a pre-release while the version is 0.x), and the same workflow then builds the package and attaches it. A tag pushed by hand also publishes (its name must match `version` in `Cargo.toml`). The build needs an arm64 runner because webosbrew publishes its toolchain for Linux only for arm64.

## Testing

- `cargo test --release` runs the Jellyfin parsing checks. `JF_FIXTURES=$PWD/fixtures cargo test --release -- --ignored quick_connect` signs in against the real server (it authorizes its own code with the fixtures login, then signs out, which replaces that login: sign in again in the simulator). `make qemu` runs the ARM build under QEMU in Docker (`tools/qemu-smoke.sh`) with stock SDL2 and a fake `luna-send` that plays a registration session: a screenshot, a TV-mode start with the Jellyfin row, a relaunch and a close, and the crash counter.
- Pressing remote buttons from a script: any tool that speaks the LG webOS pairing protocol works (for example `aiopylgtv`'s `WebOsClient.button`). Keys from a `/dev/uinput` device do not reach apps; the compositor ignores the device. The colour buttons are not available that way, so check the Options key with a real remote.
- Screen: `luna://com.webos.service.capture/executeOneShot` (webOS 6 name; Native Jelly's `capture-screen.sh` uses the webOS 4.5 `tv.capture` name, which does not exist here).

  - Under QEMU with stock SDL2 and dummy video (`make qemu`): the screenshot matches the simulator except for text smoothing and the clock; the TV-mode start writes `/tmp/tvlauncher.log`, calls `luna-send` with `-n 1 -w 5000 <uri> {}`, fetches the Jellyfin list over HTTP and caches it; the registration session's `relaunch` reloads the data and `close` exits with 0; a failed start and a SEGV each add a line to the crash file. `takeover.sh`'s crash count was tested with a made-up file.
  - Against the real Jellyfin 12.4.0 server on the LAN: resume and next-up parsing, image selection and download, the cache, and an unreachable server (the 6 s timeout keeps the cached row). Quick Connect end to end (code, authorize, sign-in, file mode 600, sign-out revoking the token) passes as a test. In the simulator: the sign-in dialog, the address pad (the broadcast found no server, as expected behind the portproxy) and the code screen, the app picker and its saved choice, and signing out. A person entering a code on a phone was not tested, nor the remote's number keys.
  - `sh tools/debloat-test.sh` passes (fake `systemctl`, `mount`, `umount`, `pkill`, `luna-send`; paths overridden). In the simulator the switches toggle, save to `state.json` and keep the list's selection. Busybox on the TV was not tried: the script uses only what CleanYourTV's scripts use, plus `grep -vx`, `tr` and `head`.
  - YouTube, against the real service from the Mac, without an account: the TV page, the base script and the OAuth client found in it, the device code (shown in the dialog), the `authorization_pending` answer to the token poll, and a logged-out browse answer whose tile format the parser was written against. **Not seen**: a token answer, a refresh, a signed-in home feed, a thumbnail download, `curl` on the TV, and the YouTube app acting on `contentTarget`.
